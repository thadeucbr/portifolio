# Matriz de cobertura — Portfólio Disruptivo IA

Atualizada em 2026-10-10. A matriz distingue implementação real, protótipo local e requisito ainda ausente. “Atendido” significa que o comportamento foi observado/testado no código; não certifica métricas profissionais nem disponibilidade em produção.

| Requisito do brief | Estado | Evidência atual | Lacuna para fechar |
|---|---|---|---|
| Recipiente mutável, navegação não linear e transições cinematográficas | Parcial | `StageShell` usa transições direcionais React `ViewTransition`, atalhos acessíveis e `prefers-reduced-motion`. | Ainda é uma única rota com troca de estágio; falta transição compartilhada/morph de thumbnails para detalhe e uma narrativa mais teatral. |
| Dark Glassmorphism, light leaks, blur 12–20 px, borda de 1 px e tokens semânticos | Parcial forte | `globals.css` implementa blur 16 px/saturate 150%, borda rgba(255,255,255,.15), cores principais e orbes. Plus Jakarta Sans e JetBrains Mono em `layout.tsx`. | Text Main usa `#F8FAFC` em vez do token exato `#FFFFFF`; não há verificação de máximo de três camadas nem auditoria de contraste/camadas em todas as telas. |
| Body text tratado, contraste e hierarquia sem sobrecarga | Parcial | Painéis usam superfícies translúcidas e texto secundário; o atlas informa conteúdo estático. | Rever todas as telas/viewport, incluir contraste automático e evitar excesso de HUD/microtexto. |
| Antigravity: cartões físicos, molas, repulsão, arrastar/arremessar/colidir | Parcial forte | `ProjectAtlas` agora usa cartões 176×64 com collider cuboide Rapier; worker aplica spring-drag, impulso limitado no release, colisões e corpos livres. Layouts Orbital/Círculo/Matriz/Triângulo e nudges por setas estão disponíveis. | Falta validação visual/tátil em browser real, layout responsivo extremo e conteúdo de skills/To-Do arrastáveis (o atlas só contém projetos). |
| Partículas/canvas com cache de sprites e sombras pré-assadas | Parcial | Malha neural usa instâncias Three.js, TSL e Bloom num Web Worker. | Não há sprite caching nem baked shadows; o campo de partículas atual tem 95 nós e movimentos calculados, não cacheados. |
| Gravity UI / AIKit / DashKit | Pendente | Não há dependência Gravity UI. | Avaliar compatibilidade e usar só onde acrescentar valor ao atlas, sem introduzir dependência ornamental. |
| WebGPU, Three.js WebGPURenderer, TSL, Bloom e fallback | Parcial forte | `neuralMesh.worker.ts` usa WebGPURenderer, TSL, Bloom e reporta WebGPU/WebGL2; canvas é transferido para OffscreenCanvas. | Não usa Rapier no worker de renderização; falta medir FPS/frametime e WebGL fallback em navegador real; AO/compute shaders em escala não demonstrados. |
| Rapier/WASM isolado em worker | Parcial forte | `semanticField.worker.ts` chama `RapierFieldSimulation`, testada com Rapier WASM real: spring-drag, throw, separação por collider e transforms finitos em viewport estreita; há quatro layouts. | Rapier ainda não é compartilhado com o mesh 3D; comportamento visual, performance/touch e colisão em browsers reais aguardam QA manual. |
| Transformers.js v4, ONNX, WebGPU com fallback WASM e Cache API | Parcial forte | EmbeddingGemma e Qwen3.5 textual opt-in rodam em workers com WebGPU/WASM, progresso e cache da biblioteca. | Falta ASR; cache ainda depende da biblioteca e não há Service Worker próprio/modo offline completo; a geração Qwen aguarda teste em navegador real. |
| Assistente contextual local / geração textual (Llama 3.2/Qwen) | Parcial implementado | Qwen3.5 0.8B ONNX q4f16/q4 está pinado por revisão e carrega só após clique; worker Transformers.js v4 tem progresso, fallback, streaming, cache no navegador, filtro de `<think>` e prompt com citações/abstenção. | Inferência final não foi executada em browser real para não disparar um download consentido de 437–485 MB sem autorização do visitante; falta validação WebGPU/WASM em browsers reais e a seleção de tools continua determinística. |
| EmbeddingGemma / busca de similaridade semântica | Atendido parcialmente | Embeddings locais e ranking por sistema são reais; fallback lexical é identificado. | Calibrar limiar/qualidade com perguntas em PT-BR/EN e mostrar citações/ranking consistente; testar WebGPU e WASM em navegador real. |
| MCP real, ferramentas tipadas, annotations e defesa contra rug-pull | Atendido parcialmente nesta branch | `POST/GET/DELETE /api/mcp` usa `@modelcontextprotocol/server`; `@ai-sdk/mcp` conecta via Streamable HTTP; ferramentas são read-only, com schema/output Zod, e a UI bloqueia drift/novos tools. Testes exercitam cliente e servidor reais. | O ranking ainda escolhe deterministamente a ferramenta; falta a decisão autônoma do LLM. A elicitation de contato ainda é um formulário Server Action local, não um pedido MCP accept/decline/cancel. |
| Server Components/RSC e fronteira servidor/cliente | Parcial forte | `app/page.tsx` é Server Component e canvas/navegação são ilhas client; MCP está em Route Handler; contato usa Server Action. | A maior parte das experiências continua em Client Components; não há streaming RSC/Generative UI via AI SDK `streamUI/useUIState`. App usa Next 16.4/React 19.3, não a versão nominal Next 15 do brief. |
| Server Actions, `useActionState`, validação e progressive enhancement | Parcial | Formulário de contato usa `useActionState`, validação server-side, honeypot e accept/decline. | Falta opção explícita cancel, proteção anti-spam/rate limit e política de retenção dos dados gravados; validar caminho sem JS em browser. |
| View Transitions API | Parcial forte | `ViewTransition` está ativo na troca de estágio, com direção e redução de movimento. | Falta morph de elemento compartilhado entre galeria de projetos e detalhe, e validação em Safari/Firefox/móvel. |
| Diagramas interativos/arquitetura como código | Parcial | ProjectAtlas apresenta estágios de execução e decisões do dataset. | Fluxo é lista textual, não grafo/diagrama interativo Mermaid; faltam ligações e estado de execução observável. |
| Live Code / sandbox com API implantada | Pendente | Há simuladores locais, agora rotulados como demonstrações; MCP consulta somente conteúdo estático do portfólio. | Nenhuma API pública de projeto está conectada; instrumentar uma sandbox real sem expor dados/segredos e com limites operacionais. |
| Mutações visuais geradas por ferramentas | Pendente | A seleção física e os artifacts são acionados por ranking/tool call, mas o conteúdo visual é predefinido. | Fazer ferramenta MCP produzir visualização de dependências/topologia em canvas, com validação/sanitização e estado identificado como gerado. |
| Conteúdo e evidência de senioridade | Parcial | O portfólio descreve cinco projetos e explicita que métricas são estáticas/não verificadas. | Faltam links autorizados a repositórios, diagramas públicos, releases, deployment ou evidências revisadas pelo candidato; não inventar provas nem expor material confidencial. |

## Ordem de execução

1. Validar geração Qwen3.5 em browser real após consentimento explícito ao download.
2. Usar o LLM para escolher um MCP tool, com schemas/annotations fixados e validação rigorosa de argumentos/resultados.
3. Elicitation MCP com accept/decline/cancel e política de privacidade/rate limit.
4. Morph compartilhado entre galeria/detalhe, além de teste tátil do atlas.
5. Diagrama como código e uma sandbox de projeto verdadeiramente executável, somente com fonte/dados autorizados.
6. ASR, gravity UI, sprite caching/AO e benchmark/visual QA em browsers reais.
